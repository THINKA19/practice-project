# 骑手登录数据契约

本文件约定前端对接和服务端验收。当前仓库提供前端与开发 Mock。

## 登录及会话

- 账密登录向 `VITE_RIDER_LOGIN_URL` 发起 POST `{ username, password }`。服务端保留已有账号，已核验的手机号可作为账号别名。
- 微信登录向 `VITE_RIDER_WECHAT_LOGIN_URL` 发起 POST `{ loginCode, phoneCode }`。两个 code 分别来自小程序登录和手机号授权，短时且一次性。服务端使用目标 AppID 对应凭据分别兑换 OpenID 和手机号。
- 两种登录均返回共享 Session 的 `IAuthLoginRes`。以 `VITE_RIDER_PROFILE_URL` 获取资料并验证 `identity: 'rider'`。退出配置 `VITE_RIDER_LOGOUT_URL`，双 Token 模式另配 `VITE_RIDER_REFRESH_URL`。配置使用同站绝对路径。
- 前端使用当前共享会话保存凭证。微信授权需用户主动触发，已登录可进入工作台，主动退出后留在登录流程。

## 服务端约束

- 后台管理稳定的 `riderId`、经核验的规范化手机号和账号状态。手机号更换由管理员核验并留痕。骑手个人资料接口只可改联系号码，登录核验号码由管理员维护。账密按账号限流，管理员重置密码后撤销旧会话。
- 服务端校验启用状态及有效门店授权后签发凭证。首次微信绑定要求手机号唯一匹配，且骑手与 `(AppID, OpenID)` 之间无绑定冲突。在事务内校验并落绑定，使用唯一约束处理并发。未开通、绑定冲突和微信调用失败分别返回可展示的错误提示，避免泄漏其他账号信息及凭据。
- 单工作会话策略由服务端实现。新登录成功后旧访问及刷新凭证失效。临时停用冻结绑定并撤销凭证，离职撤销并解绑。有在途单时按调度流程交接。
- 门店授权以 `shopId` 表达，商家与门店分别建模。任务读写校验当前会话、账号状态、门店、任务归属和具体权限。抢单及配送动作原子检查状态与版本。失效会话返回 401，仍有效但无权访问的请求返回 403。

## 开发 Mock

开发演示账密走所属模块 Mock，由共享会话 Mock 签发凭证。微信手机号兑换需在真实服务环境用微信真机联调。
