# 配送任务数据契约

当前仓库实现骑手客户端和开发 Mock。生产环境由业务服务提供运营授权、调度、订单状态联动和持久化。

## 骑手接口

- `GET /operator/rider/tasks?view=workspace` 返回当前会话的服务区、上线状态、并发上限和任务快照。`view=fulfillment` 仅返回本人已接和历史任务，离线轮询使用该视图。服务端在离线时始终排除新任务。
- `POST /operator/rider/online` 接收 `online`。上线时附带 WGS84 经纬度和可用的定位精度，服务端校验授权及服务区。下线后撤回待确认指派，保留本人在途任务。
- `POST /operator/rider/task/action` 接收 `id`、`version`、`action`、`reason`。服务端从会话读取身份与有效授权，在同一事务中复核任务状态、版本、归属和容量。已指派任务占用一个名额，确认指派沿用该名额。并发写入失败时约定返回业务码 409，客户端刷新快照。指派截止时间通过 ISO 字符串 `assignmentExpiresAt` 返回，生产回收及再派发由服务端执行。

服务区包含 `countryCode`、`cityId`、`zoneId`、`label`、`currency`、`timeZone`。未分配返回 `null`。任务保存自身服务区快照和门店 ID。配送费是订单币种的实际金额，例如 24000 VND 传 24000。联系电话和精确送达坐标由服务端按任务归属授权后返回。四个目标市场的坐标使用 WGS84。任务可返回非负整数 `itemCount`。取餐码 `pickupCode` 仅在本人待取餐任务中返回，卡片与详情按字段可用性显示。取餐地址 `shopAddress` 和送达地址 `address` 应返回独立的街道、门牌或房号，服务区标签通过 `serviceArea` 提供。

待抢单及待确认指派可返回可选的 `deliveryArea`（片区名称），此时 `address` 返回空字符串，且省略精确送达坐标。接单后按归属返回完整地址。待取餐可返回可选的 `pickupNote`（入口、楼层或取餐柜说明），配送中可返回可选的 `deliveryNote`（入口、门禁或交接说明）。详情页复制当前阶段的地址正文。

任务可选返回 `deliveryDistanceKm`（来自有效位置的送达点直线距离，单位 km）、`deliverBy`（最晚送达时间）及 `pickedUpAt`、`deliveredAt`、`cancelledAt`。时间字段为 ISO 时间。旧快照的 `settledAt` 在已完成任务中兼容为送达时间。已归档记录应清除拨号号码和取餐码。

历史页从当前骑手快照读取终态记录，按当前服务区时区筛选并分币种汇总，界面分批展示。独立历史查询、服务端分页和实际结算明细待生产接口提供。

## 状态与权限

大厅任务从 `pending` 经抢单进入 `accepted`。指派从 `assigned` 经确认进入 `accepted`，拒绝、过期和下线时释放预留。取餐后进入 `delivering`，送达后进入 `done`。取餐前可以转回大厅。真实服务应将取餐和送达同步至对应的顾客订单。

骑手接新单应同时满足国家、城市、配送池及门店授权。位置用于检查服务区和取餐距离。调岗或撤权即时停止旧区接单，已接任务按任务归属继续履约或由后台交接。生产服务需维护定位有效期，管理区域与授权变更，并限制列表、详情、通知和统计的数据范围。

## 开发 Mock

配送任务按配送池共享，骑手上下线和定位按账号隔离。30001 和 30003 可竞争河内纸桥任务，其中 30003 有门店绑定。30002、30004、30005、30006 分别属于曼谷、胡志明市、万象和雅加达。未知账号未分配服务区。直接开发演示使用站点中心作为测试定位，接口可显式传入坐标以验收跨区和半径拦截。Mock 为内存数据。
