# 桌台看板读取协议

前端约定 `GET /operator/shop/tables?shopId=...`，使用当前账号的 Bearer token。开发 Mock 按门店校验 `table.read` 权限。生产服务应按账号、商家和门店授权，仅返回已启用桌台。

响应为数组，每条包含桌台 ID `id`、门店 ID `shopId`、显示桌号 `no`、座位容量 `seats`、容量组内排序 `sort` 和当前已入座人数 `occupiedSeats`。`seats` 为正整数，人数字段为 0 到容量之间的整数，`null` 表示人数未知。服务端需在入座和离席时更新人数，包括尚未下单的客人。前端根据可信人数计算剩余座位。

旧响应缺少座位容量时归入「容量未知」。缺失、非整数或超过容量的人数按未知处理。此时可用旧接口的 `occupancy` 字段显示有人或无人，剩余座位继续显示未知。入座状态也未知时，桌台不参与看板展示和计数。前端跳过标记 `enabled: false` 或显式属于其他门店的记录。

可选字段 `seatPositions` 为按后台展示顺序排列的 `{ code: string, occupied: boolean }[]`。后台管理员可按桌配置座位编号（例如 A01 下的 1–4），由门店入座、换座和离席流程更新对应座位。编号在桌内唯一，已知容量时每个座位都应有记录。若同时提供汇总人数，两者必须一致。只有汇总人数时页面显示人数和余座。

Mock 为开发演示数据。真实接口的字段和更新时效需联调确认，服务连接沿用 `VITE_SHOP_BACKEND_ENABLED` 开关。
