# 账户资产页面

正式页面按用户确认的目录并列组织，每个页面的 UI、状态和测试归自己的目录：

- asset/index.vue：钱包余额、冻结金额、充值套餐、自定义金额和充值确认。
- asset-cash-log/index.vue：资金收支明细。
- asset-recharge-log/index.vue：成功充值记录。
- coupons/index.vue：可领、已领、失效、券号兑换；口令券领取。
- score/index.vue：积分变动记录。

card/ 和 card7/ 是原代码参考，本次不修改、不作为运行时依赖；两者除优惠券旧导航地址外基本相同，正式页面扫描排除这两个目录。三个资产入口由账户首页进入，通过 pages/routes.ts 定义路径。

## 代码归属

页面内部保留必要的 components、composables、api、models；不强制每个页面建立所有子目录。资金、充值记录和积分各自维护 API、类型与 Mock 入口，index.ts 导出外部使用的能力；钱包接口和充值规则归 asset；优惠券、积分维护各自准入。纯分页机制位于 hooks/project/usePagedList.ts、usePagingView.ts，响应结构解析位于 utils/project/paged-response.ts。跨模块通过 index.ts 使用实际需要的能力。没有依赖已删除的 shared、infrastructure/http、根级 api 或旧支付组件。

所有请求复用公共 http/alova，不修改公共请求、Mock 加载器、路由拦截器或会话设施。请求明确携带当前顾客 Authorization，数据过边界校验后显示；账号变化和页面销毁后丢弃迟到响应。

## 开发演示与真实服务

开发模式且 VITE_USE_MOCK=true 时，各模块的 mock/entry.mock.ts 经已有加载器登记。游客只能查看固定公开演示数据；领券、兑换和充值要求顾客会话。演示样本初始为余额 128.50、260 积分、3 张可用券，与个人中心摘要一致。操作完成后，个人中心重新请求同一顾客的演示状态。

- 口令券：口令 DEMO。
- 券号兑换：券号 DEMO2026、密码 DEMO；同账户不可重复兑换。
- 充值：仅开发演示，确认弹层明确标识不产生真实扣款。模拟接口返回后更新余额、资金及充值流水；重复 requestId 不重复入账。
- 四个列表页使用已有 z-paging 的内层滚动、下拉刷新、加载与错误重试样式，关闭页面外层滚动；不再混用 onReachBottom 和临时底部加载条。每次请求 pageSize=15，最后一页按剩余数量返回，不足一屏自动补页；统一触底加载，底部提示不提供点击加载。开发券池和三种流水各提供 56 条模拟数据。
- usePagingView 只对接现有分页状态与组件完成回调，不发业务请求；账号修订号由调用方提供。优惠券标签固定在 z-paging 的 top 插槽，列表顶部留 32rpx 间距，移除卡片入场动画。
- 演示状态只保存在内存，开发服务重启后恢复样本，不代表真实资产。

关闭 Mock 后，读取和优惠券操作保留旧接口路径，尚未完成真实后端联调。原代码没有真实充值下单、支付凭证和支付结果查询接口，因此生产充值保持关闭；不得把本地确认当支付成功。后续需在 asset 模块内接入正式支付及结果确认，不能用演示接口替代。

## 验证

使用 pnpm；相关测试包含 assets 各模块及 account/index 的跳转、展示和摘要。H5、小程序构建不等于真实支付、真实后端或设备验收。

## 业务边界

本目录保留钱包、充值与资金明细、优惠券、积分。礼品卡目录、赠送及领取统一归 pages/home/service 下的 gift-card、gift-send、gift-receive，不在账户资产中维护第二套实现。
