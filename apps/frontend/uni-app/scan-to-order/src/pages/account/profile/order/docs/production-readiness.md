# 我的订单生产就绪检查（2026-10-26）

范围：订单列表、详情、图片、支付、取消/删除、联系商家，以及直接关联的登录和售后代码。属于本次模块检查，不代表整个应用已获生产验收。

## 已修复

- 详情登录状态原先未接入，loginRequested 是未使用常量。现按当前顾客身份显示登录入口，首次引导，取消返回不循环跳转。
- 支付与取消原先分别加锁，可同时提交。现互相阻止，售后入口也避免与支付重叠；服务端仍需原子状态校验。
- 支付原先仅校验订单金额，NaN 余额可能绕过比较。现拒绝非法金额、余额与积分。
- 支付请求返回仅提示受理并刷新，不把空响应解释为最终结算成功。
- 列表及详情对主要容器结构进行校验，避免错误响应被解释为正常空订单。
- 列表保留旧数据时暴露刷新失败并提供重试；空列表失败也提供重试。
- 列表底部不再暗示已加载全部历史记录。

## 必须完成的生产接入，当前未闭环

1. 支付：目前只有余额支付，Mock 明确拒绝扣款。需确认订单支付金额的服务端快照、原子扣款、重复请求幂等、超时后查询，以及微信支付下单参数、平台签名、回调与最终状态查询。不要自动重试扣款。
2. 分页：list({}) 未传分页参数，模型虽含 totalPage/totalRow，但无已确认的分页合同。需后端明确页号、页大小、排序及游标，随后接入加载更多、跨页去重、分类查询和空页判断。当前不能保证展示全部历史。
3. 售后：按钮仅按订单状态判断，不能表达售后期限和商品资格。商品 afterSale、amountSingle 等字段必须由服务端提供；售后记录查询失败当前被 catch 为 null，会误当成无记录。提交需由服务端校验可退数量、优惠分摊、金额、权限和重复申请，不信任前端计算值。
4. 联系商家：Mock 分支仍是说明弹窗；正式路径通过 shopPhone 查询电话。需真实门店 ID、电话字段及平台拨号验证，不能用虚构号码拨号。
5. 图片：Unsplash 只是开发照片；shopImage 是待确认的前端字段。需真实商品快照图片与门店照片映射、受控 CDN、合法域名和图片使用授权。现有图片占位只解决 UI 失败展示。
6. 权限：页面身份检查、账户切换隔离不能替代服务端按顾客核验订单归属。需真实账户交叉访问、过期凭证、越权 ID 测试。
7. 金额/时间：需确认金额字段含义（单价或行总价、运费、优惠、退款后实付）、货币与时区。不能在未确认合同前推断字段、补零或重新计算实付金额。
8. 真实设备：弱网、离线、支付取消/超时、页面前后台、长订单号、多商品、图片域名失败和大字体尚需 H5/微信真机验收。

## 保持现有设计

- 业务 API、模型、Mock 与页面逻辑继续归订单模块，不搬到全局 Store。
- 继续使用唯一 session、既有 HTTP 与路由机制，不修改受保护目录。
- 所有订单状态均可进入详情；店名只展示，状态与商品打开详情，操作按钮独立执行。
- 图片占位组件、按账户隔离、请求代次防迟到响应、取消/删除确认和状态限制继续保留。
- Mock 只用于开发与回归，不迁入正式数据，不把模拟状态变化作为扣款或退款依据。
