# 会员码数据与后端接入参考

## 证据与边界

本次依据当前前端实现和历史参考代码补齐开发链路，未获取真实动态码接口文档、后端源码或数据库结构，未调用生产接口。本文不是数据库 DDL，也不证明存在对应数据表。

正式实现见 [api/member-code.ts](../api/member-code.ts)、[models/member-code.ts](../models/member-code.ts)、[mock/entry.mock.ts](../mock/entry.mock.ts)。完整目录职责、生命周期和验证步骤见 [README](../README.md)。

## 已知数据来源

客户身份与资料：pages/auth/session 公开入口。余额与积分：会员中心公开账户视图复用钱包 assetApi.amount，不新建资产接口。金额沿用钱包 balance 的元单位；积分使用 score。

动态码：仅开发端点 GET /__mock/account/member-code，无业务入参。由模块 Mock 返回 DEMO 前缀样本、expiresAt 毫秒时间戳和 demo:true。统一 HTTP 外层响应经现有 Alova 解包，不在业务层再次拆包。样本没有真实核销含义。

## 运行时校验

code 必须满足开发前缀和字符长度限制；expiresAt 必须为安全整数，位于接收时刻之后且最多相差 60000 毫秒；demo 必须严格为 true。空对象、数组、缺失字段、未标记的码和过期码都拒绝展示。业务不保存原始响应，不将编码内容或 Token 写入持久化。

## 身份和环境

API 请求前校验客户身份及有效 Token。开发 Mock 对已知凭证复用现有客户归属检查；刷新后未知开发凭证的处理只符合现有演示约定，不能证明真实鉴权。生产、关闭 Mock 时 API 拒绝调用演示端点，页面显示未开放。

动态码到期、页面隐藏、销毁、退出和换账户后清除；旧请求响应不能覆盖新会话状态。

## 真实后端待确认

- 服务地址、请求方法、网关、环境、客户端身份与服务端权限检查。
- 响应业务字段、外层协议、空值语义、错误码及重试规则。
- 动态码是否包含敏感信息，服务端签名、一次性使用、撤销和防重放要求。
- 过期时间格式、有效期、服务端时钟偏差、刷新频率和限流规则。
- 二维码真实载荷、条形码编码规范、跨端绘制能力和扫码设备兼容性。
- 核销接口、操作权限、幂等、扣款与积分变动、消费结果查询及异常恢复。
- 如需落库：真实表名、字段、主外键、索引、租户归属和审计规则；目前全部未知。

## 后续实施顺序

先确认接口及扫码协议，再在本模块 api/endpoints.ts、api/member-code.ts 和 models/member-code.ts 接入真实数据；按真实码类型实现渲染，并补充真实响应边界与状态测试。开发响应的 demo:true 和 DEMO 前缀规则不能直接复用为生产契约。

随后进行服务联调和真机扫码核销验证。不得通过改写公共 HTTP、Mock、Router 或创建第二份会话绕过现有边界。
