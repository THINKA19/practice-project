# 门店选择与上下文

源码核对：2026-10-28。

## 页面与职责

`index.vue`：点餐 Tab 门店选择列表。

拥有门店 API、DTO、模型、经营地区目录、地图展示和跨页门店上下文；详情与位置页面分别归 shop-detail、shop-location。

## 公开能力与依赖

`shopApi`、`toShopDetail`、`useShopStore`、`openShopList`、门店/坐标类型、地图 URL、地区目录和门店展示组件；精确清单见 index.ts。

依赖：共享会话；menu 的现有文案与平台适配；客户端路由常量。商家入驻直接进入 pages-shop/onboarding。

跨领域只通过对方 index.ts；页面只由路由加载，内部组件使用 components/组件名/index.vue。

## 状态所有权与规则

`store.ts` 唯一拥有当前门店、配送方式和扫码桌台上下文；只持久化公开门店与配送方式。列表查询、地区草稿、请求版本及滚动恢复由每个列表实例持有；电话复制反馈由 useShopPhoneContact 持有。

从列表进入门店后，系统返回及菜单的选店操作保留原列表实例、已加载页数、筛选和离开位置。`openShopList({ mode: 'resume' })` 优先通过页面栈返回已有列表，找不到或回退失败时再切换列表 Tab；新建的列表仍从第一页开始，不跨页面销毁或应用重启恢复。默认 `openShopList()` 与主动点击列表 Tab 保持重新选店语义，清空筛选并回到顶部。优惠到期、优惠列表重新显示及收藏变更使用 z-paging `refresh()` 刷新已加载范围，不先清空多页数据；位置在查询、刷新完成并更新视图后恢复。换账号继续清空旧列表，不能恢复上一账号数据。

门店列表每页 6 条，筛选后分页；关键词防抖 400ms，切换地区回到第一页，忽略迟到响应。地区从 `shopApi.regions()` 获取后台开放经营目录，不是完整行政区划；每次打开刷新，支持失败重试、空目录和失效选择清理，不回退静态样本。接口契约及后端待确认边界见 [docs/regions.md](./docs/regions.md)。H5 地图使用 Google 网页嵌入，原生端地图以目标坐标系展示。电话在小程序使用系统拨号，其他端显示号码复制面板。

## 门店分类、收藏与活动（2026-11-01）

搜索栏下提供“全部 / 优惠活动 / 我的收藏”，先公开浏览再进入需要登录的个人收藏。分类与地区、关键词同时交给列表接口，先筛选后分页。新开业不再独立显示营销标签；只有已发布、未结束的活动才展示活动卡片，包含可预览的开业优惠，没有优惠的新店不进入优惠分类。经营状态使用独立普通文字，列表省略正常营业，详情明确显示；经营状态不是活动入口。

活动区域仅展示接口排序首项有效活动，只有一个名称、日期与固定箭头。详情仅展示棕色活动名称、日期和活动说明，不显示独立简介和现金结算提示。summary 为可选旧接口字段，不参与校验和展示。未来已发布活动仍可提前宣传，结束日全天有效，次日隐藏；后端应只返回当前主推活动。

`favorites.ts` 拥有当前顾客收藏 ID 的跨页内存状态，服务端为事实源；列表移除收藏操作，保留“我的收藏”分类，收藏入口放在点餐门店头部和门店详情。未登录切换“我的收藏”只展示“登录后查看收藏门店”及品牌棕色“去登录”按钮，不自动跳转、不请求私人收藏接口；主动点击按钮才沿用顾客登录引导。登录返回保留分类并刷新，取消登录仍留在当前分类，换会话清空并忽略旧响应。已登录空列表提供浏览全部门店入口，加载失败独立显示重试。保存失败不改 UI，业务前端不持久化私人收藏。

`ShopBusinessBadge` 放在店名后，用不可点击的圆角胶囊表达唯一经营状态，长店名时允许自然换行；列表省略正常营业，不显示浏览/加购长提示，“当前门店”改为标题行小标记并保留卡片高亮。门店内部明确显示经营状态及简短“暂不可下单”说明；预计开业日期仅在接口提供时展示。优惠卡片保持独立可点击区块，不与经营状态混用。

门店卡片与活动面板统一使用“进入门店”，休息中、暂停营业、即将开业均可进入菜单浏览和加购，页面明确提示暂不可下单。活动面板进入前重新确认门店快照；普通选店不再跳转门店资料页，非营业时也不直接返回结算页。业务状态与活动是否存在互不决定。

`businessState?: open | upcoming | suspended | resting` 是待真实后端联调的显式契约，不猜测数字 status。暂停/筹备/显式休息优先；正常门店按合法营业时段（当前业务时区 UTC+7）自动判断营业/休息，包含开始、不包含结束，同起止表示全天。缺少合法时段和明确状态时，不虚构正常营业并禁止结算。

`useShopCheckoutAvailability` 拥有结算限制文案与交易前刷新，网络失败、换店或换账号停止交易。普通去结算、扫码桌台提交、拼团/砍价跳转、正式订单提交复用该入口；加号、规格、购物车数量和删除操作保持可用。前端检查不能代替后端在报价、创建订单、桌台加菜时的原子校验；购物车不锁价格、库存或活动权益。

新增收藏与活动接口契约见 [docs/db.md](./docs/db.md)，当前仅完成前端与业务 Mock，未验证真实后端或真机。
