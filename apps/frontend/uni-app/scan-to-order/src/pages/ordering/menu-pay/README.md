# 结算与支付

源码核对：2026-10-28。

## 页面与职责

`index.vue`：结算与订单支付。

顶部门店卡片携带当前门店 `id` 打开 `ClientRoutes.Ordering.shopDetail`，用于核对门店信息；通过普通页面导航保留结算页，详情返回后继续确认订单。卡片不再进入门店选择列表，右侧使用不带横线的向右尖头。

拥有结算试算、配送费、订单提交编排、购买草稿、PaymentPanel 及支付接口/规则。订单实体接口仍由账户订单领域持有。

## 公开能力与依赖

`paymentApi`、`PaymentPanel`、`usePayOrder`、`useGoodsDraftStore`、支付计划/后续动作类型和计费转换规则。

依赖：cart、menu、门店 index、账户订单、地址、资产、礼品卡与共享会话。

跨领域只通过对方 index.ts；页面只由路由加载，内部组件使用 components/组件名/index.vue。

## 状态所有权与规则

非营业显示具体不可结算原因，提交栏禁用；试算检查当前门店快照，新订单提交前复用门店 `useShopCheckoutAvailability` 获取最新经营状态，停止营业、网络失败或上下文改变时不创建订单、不清空购物车。立即购买同样适用；已创建订单的支付由原支付流程处理。真实后端仍须在报价与订单创建时原子校验经营状态、价格、库存和优惠。

`store.ts` 拥有立即购买与分享来源草稿，随会话切换清理；表单、预览和支付进度属于组合函数实例。服务端订单与到账结果不是本地权威状态。

提交锁避免重复点击；重试复用已有流程中的请求标识，身份变化与流程关闭后忽略迟到响应。支付取消不判成功，客户端回调不能代替后端到账确认。

## 三个业务入口与结算边界

- 扫桌码走 menu-cart 桌台加菜、已点和买单流程，不进入普通自取结算。桌码门店优先于缓存选店；桌台下单校验当前门店及商品归属。
- 首页到店自取与外卖配送沿用现有选店入口，显式进入时退出旧桌台上下文。没有门店通用码入口。
- 自取在当前下单门店领取，不请求或选择其他提货点，联系电话选填；包装选项沿用门店既有配置。
- 外卖要求完整收货信息；地址加载失败有独立重试状态。配送费单列，包括有效零配送费，按地址加载、缺地址、报价中或失败显示具体状态；有效零配送费显示免配送费。
- 商品小计来自当前商品快照；应付金额必须取得有效服务端试算。加载、失败、尚缺信息不能显示为有效零元，也不能支付；失败可重新计算。起送门槛使用有效报价的商品金额。
- 切换方式、地址、商品、优惠、账户等使旧报价失效；迟到响应不能恢复旧报价。

开发 Mock 补齐 /order/create 的试算和演示订单创建，固定配送费 3 使用现有演示金额单位，仅为样本。试算不创建订单，正式创建保留请求幂等及实际商品明细，不模拟真实扣款。商家协商配送费需后端报价、顾客确认和商家操作接口，本次没有伪造该能力。

## 电话与本次配送地址

自取电话使用 `phone-input`，选填空值可提交，非空值按选择的国家区号校验并在提交前转为国际格式，写入既有 extJsonStr 的“联系电话”。换账号清空电话草稿。

配送进入时读取当前账号地址列表：本次选中且仍存在的地址优先，其次默认地址，再其次唯一地址；有多个地址但没有默认时提示选择，列表为空才提示添加。选择、取消、新增保存及再次显示时保持本次选择，不以“设为默认”代替本次选址。同账号同门店切换自取/配送保留选择，换账号或换店清除；删除当前地址后回退现有默认。

地址通过模块公开的 fullAddress 组合国家、地区和详细地址，使用既有订单 address 文本字段提交，不自行假定后端支持新结构化字段。缺坐标、非法坐标或距离计算失败用 null 表示未知；普通配送缺坐标时由现有服务端试算核价，不当作零公里；达达配送缺收货坐标时提供补充定位入口，获得有效运费前不允许提交。已有地址表单仍允许纯文字地址；真实定位、结构化地址协议和配送报价需后端联调。

## 结算体验调整

本页不再选择或提交优惠券，会员卡能力保留。商品清单标为商品小计，底部应付金额仅使用有效服务端报价。自动试算缺地址时不弹提示，底部选择地址入口可直接打开地址列表。

当前用户资料接口没有手机号字段，自取使用默认地址或唯一地址的有效联系人电话并标注来源，允许修改；不会覆盖本次手动输入或清空，加载失败允许重试，也不阻塞选填电话的自取报价。换账号、离页忽略旧请求。电话输入统一使用公共组件同排展示国家、区号和小下拉折角，不提供页面专用样式分支，不再单列切换文字。地址与自取电话均保持标签、国家区号、号码输入框单行排列；自取输入提示为选填手机号，不再常驻用途说明。

## 当前现金下单流程

普通自取和配送结算只提交订单，不再打开余额或第三方收银台，也不弹二次确认。底部固定提示现金结算，成功后进入订单页；报价未完成时显示商品小计和运费未计入提示。具体实现、配送计费建议及后端边界见 [配送与现金提交](./docs/delivery-and-cash.md)。

创建成功后进入刚创建的订单详情，展示订单提交结果及下一步；底部使用应付金额，不把现金未收款写成实付。普通配送缺坐标时由既有服务端试算接口核价；第三方配送缺坐标提供当前地址补充定位入口，只有明确超范围才要求更换地址。后台区域规则配置仍需后端支持。

结算商品清单、购物车弹层及结算门店卡复用已有图片组件，使用商品 pic 与门店 pic/photos；图片缺失或失败显示占位。下单扩展记录计价国家及门店展示快照，订单详情和列表复用门店域的纯币种格式规则，越南、老挝保留万计单位，不进行换汇。

提交成功提示在当前订单详情真实数据加载且页面呈现后显示 2500ms；每次提交流程仅提示一次，普通查看订单或页面隐藏时不提示。详情页常驻结果与现金说明保留，金额数字沿用结算页 #c93636，标签为深灰。
