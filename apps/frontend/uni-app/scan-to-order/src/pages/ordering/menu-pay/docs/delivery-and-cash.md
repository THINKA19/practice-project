# 配送核价与现金提交

## 当前已经实现

- 电话保持标签、国家区号、号码输入框单行排列，缩短标签占位及间距；地址入口使用无横线的右折角。
- 地址存在不等于配送资格已确认。普通配送缺坐标时先请求服务端按完整地址核价；第三方配送明确要求坐标时提供补充定位。真实超范围才提供更换地址，原因只在地址卡展示。配送费处显示简短状态；不再推荐改为自取，也不因普通地址缺坐标反复要求换址。
- 未取得完整报价时，底部显示已知的商品小计，并明确配送费未计入；只有有效报价后才显示应付金额。已知距离没有覆盖档位时不能省略档位尝试默认收费；未知距离不传本地档位，交由服务端按区域或其他门店规则核价；乱序档位选择最小覆盖档。
- 页面底部固定说明：仅提交订单，无需线上支付。自取提示到店现金结算，外卖提示收货时现金结算。
- 点击提交直接调用既有订单创建接口，不弹二次确认，不调用资产余额、余额扣款或微信/支付宝支付。创建成功后才清理购物车并进入当前订单详情；失败保留购物车、报价，重复请求使用相同 requestId。成功响应后仅继续同步及跳转，不再创建第二单。
- 现金方式通过既有 extJsonStr 的“结算方式=现金结算”传递。列表、详情根据服务端返回的标记展示待现金结算，阻止线上支付入口；不把已提交当作已收款，不伪造 paid 状态。

## 运费按什么计算

收货人只决定联系对象，不决定运费。建议由门店后台配置配送区域、费用及起送条件：区域覆盖是资格判断；费用可用区域固定费，或区域内按距离阶梯计费；满额免运费也由服务端统一判断。海外文本地址较多、尚无可靠定位时，区域固定费更容易落地，但必须使用稳定地区编码，不以自由输入的地址文字猜测区域。

现有前端契约只有距离档位和 /order/create calculate=true 报价，不能据此宣称区域计费已经接入。实际运费使用 amountLogistics，最终金额使用 amountReal，明确返回 0 才是免配送费。Mock 固定费用仅为演示。

## 海外地址与距离的后续落地

1. 地址选择服务需要覆盖实际经营国家，并将用户确认的完整地址、经纬度、稳定地区编码及坐标系保存到地址接口。文字地址可保存；普通配送先由服务端核价，不能仅靠文字在前端计算路线距离。地址编辑提供可选地图位置，确认后保存坐标，取消不覆盖草稿。
2. 路线距离及配送资格应由服务端统一计算；前端现有直线距离不能等同骑行路线。地图服务由经营国家的覆盖、准确度和实际调用量选择，本次不加入未经确认的地图供应商或密钥。
3. 报价接口应返回明确的可配送/不可配送/资料不足状态、费用、原因及可选的有效报价标识；正式创建再次核验门店、范围、库存、费用及报价有效性。
4. 若采用区域收费，需要后端增加或明确区域规则契约；没有该契约时不隐藏缺定位问题，不在前端硬编码一个“默认运费”。

## 后端联调边界

真实后端必须接受现金结算订单、保存并在列表和详情回传结算方式，且不以线上付款作为接单前提；线上扣款接口也应拒绝现金订单。当前前端扩展标记和本地 Mock 不证明真实服务已实现这些约束。取消、商家接单、配送和现金实收继续由服务端状态及权限控制。网络结果不明时依赖 requestId 服务端幂等，不能仅靠前端按钮锁保证不重复。

## 提交结果与配送核价调整

直接提交成功后打开当前订单详情，只有真实详情加载成功且订单编号匹配时才展示提交结果；显示编号、服务端状态、应付金额及下一步，详情读取失败允许重试，不重新下单。不把提交成功等同门店已接单或现金已收取。

本次未新增区域规则接口或商家后台配置。普通配送使用既有 /order/create calculate=true，缺坐标或本地档位读取失败时可由服务端决定运费；有效非负 amountLogistics 和 amountReal 均返回后才允许提交，失败提供重试与联系门店入口。真实服务必须实现地址配送资格与区域规则校验，Mock 报价不能证明生产区域配置有效。
